# 不同输入条件的可运行例子

运行 `python run_examples.py --out outputs/examples --vision`，脚本会生成并实际
执行 A–I 九种输入情况。所有自动生成的数据明确标为合成，不能作为真机验证。

| 例子 | 有什么 / 缺什么 | 实际处理 | 应看到的结果 |
|---|---|---|---|
| A | 有发送动作和实际 q；没有图像、力矩 | 事件时刻积分、一阶响应拟合、留出整段预测 | 恢复已知时间常数与延迟；不声明接触对齐 |
| B | 只有实际 q | 时间、数值审计；控制和接触分支降级 | 接触估计 `skipped`，不会补出摩擦 |
| C | 只有物体滑停运动；没有机器人动作 | 明确脱离区间、初速度和水平面后拟合摩擦 | 估计有效滑动摩擦；不估计全部质量/刚度 |
| D | 有实际推杆和物体运动；无力矩 | MuJoCo 规定推杆运动，物体自由演化 | 拟合接触对摩擦并预测留出片段；尚无机器人受力反馈 |
| E | 有实际关节状态和力矩；无图像 | 逆动力学残差、多平滑窗口诊断 | 模型残差及敏感性；不自动当作真实接触力 |
| F | 有完整模型、执行器、策略；无真实数据 | 机器人与物体一起积分，闭环观察并发动作 | 接触反力影响机器人；仅说明仿真机制正确 |
| G | 有 RGB、相机标定、fit-only 种子；无力矩 | 真正优化 3D 高斯参数 | 高斯 PLY、留出渲染、PSNR/轮廓指标；非接触几何认证 |
| H | 有 RGB 和相机标定；没有深度 | 多视角平面扫描估深、跨视角筛选、TSDF | 有观测支持的局部稠密表面；缺失区域保留 |
| I | 有标定 RGB-D | 深度一致性和 TSDF 融合 | 稠密表面、体素精度与观测覆盖；仍要独立几何检验 |

额外情况：

- **无位姿照片**：`03_images.py sfm` 实际调用 CPU COLMAP。需要重叠、静态场景
  与可辨认纹理；尺度仍未知。本次程序生成场景只注册少量视角，已记录为覆盖失败，
  不能自动进入高质量物理资产流程。
- **有图像但没有标记**：当前 `03_images.py track` 只实现已知标记跟踪；一般物体
  分割与无标记六自由度跟踪需要另接后端，不能假设自动可靠。
- **无图像但有 CAD**：直接用 `08_assets_and_layouts.py asset` 登记；不具备真实 RGB
  输入验证。摩擦属于接触表面对，不能从 CAD 名称唯一确定。
- **有真实成对策略试验**：先用 `paired_protocol.py freeze` 固定任务容差、策略和
  模型版本，再运行 `09_evaluate_policies.py` 与 `paired_protocol.py audit`。
  如果只有训练演示、终止标记或作者汇总成功率，不应进入真机替代认证。

## 流程中的质量控制

1. 保留源摘要、单位与语义；动作和实际状态不混淆。
2. 相机与机器人时间对齐独立于控制延迟；图像缺检不被当成测量。
3. 用独立末端观测校准；检测基座与关节零位的参数歧义。
4. 视觉、碰撞表面、物理参数分别登记；未知表面不因补洞变成已验证。
5. 拟合只用 fit 回合，测试用独立回合；同数据不能重复入库充当独立证据。
6. 检查接触参数敏感性、数值步长和不同条件的预测；单条轨迹吻合不证明唯一真值。
7. 生成布局先是候选；还要检查稳定性、可达性、路径和现实复位。
8. 最后比较同任务多策略的闭环真实/仿真结果，记录成本、排序和误判风险。

后处理能检测和限制错误；缺失的现实观测不能通过后处理凭空获得。
